# OctoAcme Project Management Documentation

Welcome to the OctoAcme Project Management Documentation hub. This collection of documents outlines the comprehensive project management processes, methodologies, and best practices used across all OctoAcme initiatives.

## Overview of OctoAcme Project Management

OctoAcme follows a structured, customer-focused project management approach designed to deliver value iteratively while maintaining clear ownership and accountability. Our methodology is built on five core principles:

- **Customer-first**: Prioritize customer value and usability in every decision
- **Iterative delivery**: Deliver small, testable increments rather than large, monolithic releases
- **Clear ownership**: Every project has a named Project Manager (PM) and Product Lead for accountability
- **Data-informed decisions**: Measure impact and iterate based on evidence rather than assumptions
- **Psychological safety**: Encourage feedback, experimentation, and learning across all team members

### Key Lifecycle Phases

Our project management lifecycle follows a proven five-stage approach:

1. **Initiation**: Define the problem statement, identify stakeholders, and establish high-level timelines
2. **Planning**: Detail the scope, allocate resources, set milestones, and identify dependencies
3. **Execution**: Build and test features, conduct reviews, and iterate based on feedback
4. **Release**: Deploy to production, verify functionality, and communicate with stakeholders
5. **Retrospective & Continuous Improvement**: Capture learnings, identify improvements, and plan next steps

### Core Roles

Every OctoAcme project includes these essential roles:

- **Project Manager (PM)**: Coordinates delivery, manages schedules, tracks risks, and owns communications
- **Product Manager (PdM)**: Defines outcomes, prioritizes the backlog, and measures success
- **Developers**: Implement features, collaborate on design and testability
- **QA/Testing**: Validate quality against acceptance criteria
- **Stakeholders**: Provide inputs, feedback, and approvals

### Communication & Governance

- Weekly sync between PM + PdM
- Twice-weekly standups for delivery teams (or as agreed)
- Monthly stakeholder updates
- Ad-hoc escalations as needed
- Key artifacts kept updated: Project Charter, Roadmap, Sprint Backlog, Risk Register, Retrospective notes

## Best Practices

### Documentation Standards
- Keep the Project Charter updated in your project repository
- Maintain a current Risk Register throughout the project lifecycle
- Document decisions and action items from all retrospectives
- Update sprint/iteration backlogs weekly

### Using These Docs with Copilot Spaces
- Add process-specific docs to `.copilot/` if you want Copilot Spaces to use them as context
- Reference these documents when creating project templates or onboarding materials
- Keep these docs synchronized with your actual project practices

### Integration with Your Workflow
- Adapt the templates and processes to your project's specific needs
- Use these docs as a baseline and enhance based on team feedback
- Review and update documentation during each retrospective
- Share relevant sections with new team members during onboarding
